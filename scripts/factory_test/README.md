# 电机出厂总测

## 自动工位界面

双击本目录 `产线测试.pyw`，或在项目根目录运行：

```powershell
python -m scripts.factory_test.gui
```

正式入口默认真实工位，设备监视开启，串口选择 `auto`。每台电机都必须由工人点击“开始测试”：

**接线 → 点击开始 → 自动执行 → 取下并贴标 → 换下一台 → 再点击开始。**

上位机只保留这一套正式界面和入口，不再发布预览版、测试版或临时联调版。
工位配置中的模拟开关已移除；旧配置内的 simulation 字段不会将正式入口切换为模拟。
研发离线自检仍在内部使用隔离数据并禁止硬件/网络，不属于单独发布的软件版本。

发布 Windows 单文件 EXE：`python -m scripts.factory_test.build_release`。
默认生成 `dist/电机产测软件/` 和同级 `电机产测软件-部署包.zip`，两者是同一套软件的文件夹和压缩包，
包含驱动、配套源码和离线自检结果；构建器拒绝覆盖已有目录。更新时先构建核验，再将旧包归档后替换。
发布包预设文档中的正式服务地址，不包含开发机密钥或历史报告。新目录可用 `--output` 指定。

| 服务 | 新工位默认地址 |
| --- | --- |
| SN 取号 | `https://www.mirrormetech.com/mes-api/open-api/module-sn/batch-generate` |
| 报告登记 | `https://www.mirrormetech.com/mes-api/open-api/test-report` |
| 本机打印 | `http://127.0.0.1:9876`，状态 `/api/status`、打印 `/api/print` |
| OSS | `https://oss-cn-hangzhou.aliyuncs.com`；Bucket `mirrormetech-mes-testreport`；Region `cn-hangzhou`；前缀 `test-report` |

这些地址仍可在“工位配置 → 服务接口”修改。API Key 和 OSS 凭据须由现场填写；
已有工位文件中的显式地址仍优先于新默认值。预设地址本身不能证明对应服务已部署或已完成联调。

- 顶部菜单：自动产测、电机调试、工位配置。主页显示设备连接、步骤、结果和底部日志。
- 右下角“打开日志目录”和“打开报告目录”均打开文件夹，由现场人员选择具体文件。
  日志目录按真实/模拟模式隔离；报告目录为当前模式的工件目录，每件保留自己的报告和原始数据。
- 界面和工位配置使用统一白色底色；工位页不显示电机 SN，“产品 / SN”统一配置项目、分类、工厂、硬件版本和日期。
- 硬件版本集中配置 ABCD，自动组成 0221 等编码，供临时 SN 与 MES 取号共用。
  A（结构版本）和 D（硬件版本）为一位数字输入框，无下拉框或重复描述；B、C 保留可编辑的下拉框。
  项目、分类、子分类、工厂、日期和 BC 均可直接在下拉框内输入，例如 B 位输入 2。
  下拉列表只是常用选项，允许直接输入新代码，不按预设枚举判断业务有效性，也不会自动覆盖手填字段。
  输入框即时限制长度：项目 2 位，分类/子分类各 4 位，工厂 2 位，ABCD 每位 1 位，日期 6 位；超长键入和粘贴直接拦截。
  产品字段回车或移开焦点时按已明确的位数和字符格式保存；格式不符时提示并保留上一份配置。
  B 为 GD/ADM；C 为 C2_jieke、C2_xinzhi、C2_PRO_jieke、C2_PRO_xinzhi、A2_jieke、A2_xinzhi。
  A/D 的数值不作为白名单，0223 等新版本沿用同一 BC 的测试参数。尚无测试参数的 BC 组合可保存配置，自动产测不猜测测试负载。
  调试的通用使能不要求 SN 或型号出现在预设表中；芯片平台 B 只用于选择 GD/ADM 不同的标零/校准协议。
- 电源和测功机串口用 `auto` 和当前 COM 列表下拉选择，保留已保存的离线端口。
- CANable SN 下拉框只列出当前在线的 SN；只有一只时自动选中连接，多只时由工程人员选择。
  没有设备时列表和选择均为空；拔下后清空离线选择，当前没有运行任务时可自动选中新出现的唯一设备。
- 每 0.5 秒在独立后台线程枚举并更新 USB 状态。
  使用 Windows SetupAPI/CM 读取当前 PnP 元数据，刷新过程不打开 USB/CAN 通道，也不启动 PowerShell。
  运行中的测试或调试连接保持原适配器，不因新适配器插入而切换连接。
  串口/打印设备检查每轮间隔缩短至 2 秒，各项查完立即显示，不等待打印服务超时后一起刷新；实际周期还包括设备响应时间。
- 本地状态文件仍采用同目录临时文件、fsync 和原子替换。Windows 5/32/33 拒绝替换时最多尝试 6 次，
  总等待 0.385 秒，失败则保留原文件并报错；该重试只提交同一份本地数据，不重新执行服务请求或电机动作。
- 连接状态通过实际只读查询/有效反馈确认；电源输出关闭也可正常显示已连接。
  测试中不另开串口探测，避免与测试争抢设备。
- 接入只做探测。点击开始后才写工位 ID、基础 SN、校准、KT、TN、MES 取号、正式 SN、打印、报告和上传。
- 来料优先探测 ID 1；无响应则扫描其他 ID。写入前完整扫描，确认仅一台后改为保存的目标 ID。
- 临时 SN 自动生成为 `12 个字符 0 + 硬件 ABCD + 10 个字符 0`，共 26 位。
  例如硬件 0221 对应 `00000000000002210000000000`。项目、工厂、日期和流水字段在临时号中全部为字符 0。
  临时号不单独配置、不打印、不上报，正式 SN 仍由 MES 按工位产品信息分配。
  本件日期在点击开始后固定，MES 取号沿用本件日期。取号地址和 API Key 在“服务接口”配置。
- MES 取号重试复用持久化的 requestId/参数，打印逐条检查结果；打印状态未知不盲重打。
- 异常自动停止后续流程、尝试停机、保存并隔离本件记录，工人无需执行恢复、归档或协议判断。
  原 SN、请求与打印状态不会删除。工程补处理入口在设置的管理页内。
- 报告上报沿用原 OSS + MES 协议：PNG 和两个 CSV 可靠保存后提交持久队列，独立后台上传并保存 MES 回执。
  网络故障不阻塞下一台，不改变测试 PASS；重启后继续补传。最后一步“提交报告上传队列”不代表远端已经接收。
  页脚分别显示待传、需处理和已完成数量。配置位于“服务接口”，地址可独立填写或读取外置 upload-config.json。
  上传配置支持原有三个凭证字段和 mes_url；新工位默认正式地址，已有报告保持原环境绑定。
  会话目录保持 UUID，按正式 SN、北京时间和会话生成兼容原 MES 的稳定 reportKey，不搬动数据。
- “服务接口”分为 SN 取号、标签打印、报告上报、OSS 存储四页。地址、接口路径、鉴权请求头名称和密钥均可在界面设置；
  OSS 支持 Endpoint、Bucket、Region、目录前缀；打印支持名称和每台份数（正整数，默认 1）。超时与重试不增加设置项。
  界面已移除旧上传配置文件路径，地址及密钥在服务接口内集中配置；历史配置仍可兼容读取，待传报告的目的地不会改变。
  服务字段先暂存，点击“保存并关闭”后与密钥一起原子保存并生效；编辑到一半不会切换后台目标。
  密钥掩码显示，使用 Windows 当前用户保护的密文保存在 station.json 中，日志/工件配置快照没有明文密钥。
  同一 Windows 用户重启软件自动恢复，换电脑或用户后应重新录入密钥。界面填入的密钥优先，空白字段兼容旧环境变量/上传凭证文件。
- 电机调试页为左侧三幅波形、右侧参数与控制面板。自动探测并回填实际 ID，连接不使能，可提前预设目标。
  进入调试页自动连接；没有电机时在后台继续只读探测。曾执行状态改变指令后发生异常、或失能/释放未确认时，不盲目自动重连。
  两页切换先暂停旧模式、请求停机并等资源释放，再开启新模式；返回产测恢复设备监视，开始测试仍由工人点击。
  页面立即响应，扫描/停机在后台完成；资源释放失败时保留日志并暂停交接。
  连接成功后立即启动目标 1 kHz 的后台收发，未使能时也采集位置、速度、扭矩及温度。
  未使能使用 `0x100 + ID` 的 RPDO5，所有目标及增益固定为零，不发送会自动使能的 `0x400 + ID`。
  明确点击使能后才使用控制帧并周期保持最新目标；点击停止后确认失能，恢复零目标状态采集。
  默认实时更新，已移除手动/实时选择和“下发参数”按钮；滑块、滚轮、文本输入均直接更新待发送目标。
  点击使能时读取当前界面值，先完成零目标使能交接，再使用当前预设；停止后保留预设、继续发送零目标状态采集。
  连续编辑以 20 ms 节拍合并到最新值，不等待拖动结束，不排队补发旧目标；未完成的数字输入保留上一份有效目标。
  橙色曲线为界面待发送目标；日志及显示 CSV 同时保存 enabled 和实际发送目标，避免把未使能预设误认为实际输出。
  参数更新与后台 CAN 发送频率独立；暂停波形不停止通信。
  Python / Windows 采用尽力调度，不补发积压周期；实际发送率、最大间隔、超期与反馈限流写入日志，未实测时不宣称硬实时 1 kHz。
  界面约 100 Hz 获取最新状态，绘图目标 60 帧/秒，界面事件分批处理、每批有时间上限；数据缓冲覆盖完整 30 秒显示窗口。
  绘图复用 Canvas 图元，按像素保留极值，恒定目标压缩为水平线；目标与反馈均为实线，重合时保留两种颜色。
  横坐标固定为窗口内的相对时间（时间 / s），小数统一精度；纵轴立即扩展、延迟收缩，避免噪声引起逐帧缩放。
  曲线减细：目标线宽 1.5，反馈线宽 1。参数滑块及输入框支持鼠标滚轮，位置滚轮及拖动步进为 0.1 rad，文本可直接输入精确值。
  固件版本按十进制显示，例如 0x00F5 显示为 245。
  调试连接中仍可打开工位配置；编辑先暂存，保存时异步停机并释放旧连接，再按新配置自动连接，不自动恢复使能。
  位置、速度、前馈、Kp/Kd 支持输入和滑块；可暂停/清除波形、保存显示数据。
  保存的是界面采样数据，不宣称包含每一包 CAN 反馈。
  上位机版本统一由 `version.py` 定义，本次为 `v1.0.2`；标题栏、全局右下角、Windows EXE 属性、启动/连接日志和发布清单保持一致。
  后续每次修改并发布都递增版本号（例如 `v1.0.3`），同一源码的重新打包不额外递增。
- 清错、标零、校准已接入，执行前必须失能；先释放周期收发通道，再进入维护会话。
  ADM 标零使用 0x2070 回调，GD 使用 0x2002=3；清错使用 0x2002=0xFF。
  校准继续使用下述完成检查。今天没有执行真实设备操作。

配置位置：`%LOCALAPPDATA%/MirrorMe/FactoryStation/station.json`。
工件目录：`data/<会话UUID>/`。旧版留下的 `ui-review/` 数据保留，不会混入生产上传队列。
工件 station.json、summary.json、CSV、report.png 保留流程与测试证据。
旧脚本原有 data 目录不迁移。

### 服务协议与配置项对应

已对照《20261021-模组SN获取与标签打印对接文档（工装侧）》V1.0 及项目报告上传协议：

| 协议内容 | 上位机配置位置与行为 |
| --- | --- |
| 取号服务域名、端口、基础前缀、接口路径 | 服务接口 → SN 取号：MES 基础地址、取号接口路径 |
| X-Api-Key 鉴权 | SN 取号/报告上报：Key 请求头名称和各自的 API Key，默认名称 X-Api-Key |
| projectCode、materialCategory、materialSubCategory、factoryCode、hardwareVersion、productionDate | 产品 / SN：集中配置，可下拉或按位手输；临时 SN 共用硬件 ABCD |
| 本机打印服务及 GET 状态/POST 打印路由 | 标签打印：服务地址、状态查询路径、打印接口路径 |
| printerName、copies | 标签打印：打印机名称、每台打印份数 |
| 报告 MES 完整 URL | 报告上报：完整地址，支持现场自定义接口路径和端口 |
| OSS Endpoint、Bucket、Region、AccessKey ID/Secret | OSS 存储：地址、桶、区域和两个密钥 |
| test-report/{yyyyMM}/{sn}/{reportKey}/ | OSS 存储：目录前缀（默认 test-report，可空）；其余层级自动由本报告生成 |
| 旧上传凭证 JSON | 报告上报：可填写原文件路径，界面尚未填写的密钥可从中读取 |

requestId、reportKey、SN 本件关联、测试时间、文件清单及 fileCount=3 自动生成；取号 quantity 保持 1，
避免单件电机一次分配多个号码。工装标识按此前需求不新增输入，未传 fixtureId 时由 MES 以来源 IP 留痕。
CODE128、50×15 mm 和标签排版由打印服务实现，当前协议没有工装侧版式参数，不添加无实际作用的配置。
OSS 与 MES 后端需要指向相同存储；报告 API 只提交对象 Key，不提交桶名/读取域名。

待传记录封存 MES 地址及 OSS 地址、桶、区域、目录前缀。更改目标不会将旧记录自动迁移到新环境；
恢复原配置后可继续补传，原文件、哈希和回执保留。密钥更新会为新后台任务建立独立凭证快照，
正在收尾的旧任务不会混用新密钥和旧地址。旧版无 OSS 目标字段的记录按原默认桶/目录解释，不将其当作新桶的成功。

### 连接周期诊断日志

`logs/production/` 保存真实日志，`logs/preview/` 保存模拟日志。识别到电机时即创建
`motor-YYYYMMDD-HHMMSS-唯一编号.log`，未点击开始也有记录。持续无响应 2 秒后确认断开并写结束记录；
短暂通信中断、改 ID 和写 SN 引起的软复位不会主动拆成新文件。测试结束后仍继续记录到确认断开。
软件退出和调试断开会记录各自的结束原因，不冒充物理拔线证明。

记录包含：软件版本/构建信息、启动编号、线程、时间、配置快照、设备状态变化、来料 ID/SN、
流程会话和 requestId、步骤起止及耗时、SDO 写入和应答、SN 回读、校准进度、测试参数/统计和判定、
取号重试、打印返回、报告路径、OSS 上传和 MES 回执、异常堆栈/原因链以及停机收尾提示。
界面遥测按约 1 秒采样写入诊断日志；高频波形仍由原 CSV 保存，不逐帧刷日志。
密钥、认证字段和已注册凭据会脱敏，不导出环境变量全集或凭证文件内容。

每件 station.json 的 connection_log/connection_logs 关联连接日志；后台补传继续写回原连接日志，
不会混到下一台电机。没有电机时的启动、配置和工位异常记录在 station-YYYYMMDD.log。
界面异常和日志保存失败也会明确记录/提示，日志故障不能阻断必要的停机收尾。

保留最近 **30 天**的日志，以文件最后更新时间为准。启动时和运行中每小时自动检查；
只删除日志目录内由本功能命名且超过 30 天未更新的日志，正在连接的日志不删除。
CSV、测试报告、工件状态、待上传任务和回执不参与清理。超过保留期后才完成的补传写入当天工位日志，
附带原连接日志标识，不重新创建已到期的旧日志。旧版 operator.log 保留原文件，不再追加。

### 现场按阶段定位（2026-11-06）

后台记录与界面显示分开：工人仍只看开始、进度和结果；底部日志显示失败阶段、错误编号、
排查方向和本次日志路径。文件保留完整上下文及异常堆栈，不依赖工人复制控制台内容。

- 每条事件包含北京时间（毫秒）、启动编号、事件序号、线程、运行时长、日志文件和适用的连接/会话/步骤标识。
  版本、构建、Python、启动参数、配置快照及配置变更供核对现场运行版本。窗口初始化失败也尝试写当天工位日志。
- 空闲设备检查记录适配器候选、串口描述/VID/PID、测功机候选及反馈、电源识别与读数、打印服务响应。
  周期探测中预期的“某个 ID 无响应”汇总记录，避免每个空 ID 都生成错误堆栈；意外故障仍保留异常。
- 维护操作记录 SDO 节点/索引/子索引、长度、CAN ID、原始请求、超时、原始应答和读回值；
  写入失败保留是否进入写调用及 ACK 未确认状态，失能请求、应答、校准停止未确认和释放异常分别记录。
- HTTP 每次有本地 http_id，记录地址、方法、超时、代理选择、请求参数、状态、耗时及服务端 request-id。
  HTTP 错误、非 JSON/网页应答也保留正文摘要；正文摘要最多 16384 字符，超出明确标记 response_truncated，
  同时记录原始字节数。打印和取号接口不自动跟随重定向，避免隐式重提交。
- 打印有独立 print_job_id（仅本地追踪，不是服务端幂等键）。探活、提交、应答、逐 SN 判定和确认分别记录。
  online=false、状态格式错误、单条失败、SN 不匹配、结果缺失、份数/总数矛盾和响应未知分别区分。
  缺失协议中的可选统计字段可以正常处理；矛盾或不完整的应答不会判为打印成功。
- 取号记录固定 requestId、冻结参数、每次应答/重试和最终 SN；报告记录路径、文件大小/SHA256、复用的 OSS 回执、
  上传次数/退避、服务地址、MES 正文与匹配回执。原始异常在包装成上传提示前写入日志。
- 异常的 diagnostic 包含稳定错误编号、排查方向、异常类型/模块/消息、errno/winerror、路径、
  HTTP 状态、协议上下文及原因链。未知故障保留 UNEXPECTED_EXCEPTION 和堆栈，不猜测根因。
  工件失败状态保存也失败时，同时显示原始故障和保存故障，不用后一个错误覆盖前一个。

常见定位入口：

| 错误编号/事件 | 已知事实 | 排查方向 |
| --- | --- | --- |
| CONNECTION_REFUSED / printer.status.failed | 本机目标端口拒绝连接，尚未提交本次标签 | 服务进程、自启、地址和端口 |
| PRINTER_OFFLINE | HTTP 服务可达，但返回 online=false | 返回正文、USB、驱动、打印机名称和设备面板 |
| PRINT_ITEM_FAILED | 服务明确报告本条 SN 失败 | results 中 message，对照打印服务日志 |
| PRINT_ACK_INVALID / PRINT_ACK_CONFLICT / PRINT_OUTCOME_UNKNOWN | 客户端无法确认本条标签结果 | 不自动重发；维护人员核对实体标签和服务日志 |
| MES_REQUEST_ID_MISMATCH / MES_SN_* | 取号结果与本件请求不一致 | 同一 requestId 的请求、产品参数及服务应答 |
| REPORT_MES_HTTP / REPORT_RECEIPT_MISMATCH | HTTP 被拒绝或回执不能证明本报告已登记 | 原 reportKey、响应正文、服务端 request-id |
| DISK_FULL / flow.persistence.failed | 文件持久化失败 | 磁盘空间、目录权限及原工件状态，停止后续副作用 |

现场可先按本件连接日志找 flow.failed/flow.step.failed，再使用 session、requestId、print_job_id、
http_id 或 reportKey 对照相邻事件；补传归属仍以工件 station.json 的 connection_log 为准。

客户端日志只能证明它观察到的结果。打印接口报告成功不等于人工验过条码，
online=false 本身也不能区分缺纸、开盖、USB 或驱动问题；这些内部原因需打印服务返回或现场设备证据。
离线故障注入用于验证分支和诊断信息，不替代 USB 实体打印、真实 MES 或电机联调。

### 校准协议核对范围

已对照本机 `Desktop/mc/2.Firmware/ADM32F036_mc_app/user/` 和
`Desktop/c1_driver/Firmware_app/Source/`，今天没有连接电机或更改驱动器源码：

- SN：0x2004～0x200A，逐段 4 字节 expedited SDO 写入（0x23），26 字节 ASCII 加 2 字节零填充。
  最后一段触发重启，之后重新连接并完整读回。中间分段失败不盲目重写。
- ID：0x2040 写 1 字节（0x2F）。ADM 回调会立即复位，可能没有 ACK；GD 启动时缓存 ID，
  需写回未改动的 SN 最后一段触发既有重启回调。两者均须在目标 ID 完整读回原 SN，不能凭 USB 完成放行。
- 校准：0x2002 写 2 字节 0x00F1（0x2B），SDO ACK 仅代表接收命令。
- ADM：清除并读回 0x2072=0，再触发校准；0x2072 再次为 1 且 0x2000=0 连续确认两次才放行。
- GD：当前没有 0x2072；新机可依据 ERR_ENC_CALIB 0x4000 清除及错误码为零确认。
  对已经校准的 GD 电机，现有接口不能证明本次完成，暂时拒绝自动重校准，待补协议。
- ADM 校准态会重新设置 RunSignal=1；现有失能 ACK **不足以证明中止校准**。
  校准中止/异常会明确提示切断工装电源，真实上机前需要确认/完善固件的校准停止机制。

今天验证：模拟完整流程、配置持久化、故障阻断、幂等恢复、逐条打印判定与协议帧离线测试。
这些不代表实际校准、MES 联调、实体出纸或云端上传已通过。

## 报告标准与指标

实际产品标准在本脚本 `app.py` 的 `LIMITS` 配置。扭矩输出误差初版标准为理想线偏差≤5%FS，可修改。
电机特性曲线只展示双轴曲线以及最大扭矩、最大转速和最大功率，不设标准、不作PASS/FAIL判定。
两项测试都必须完整执行；异常、用户停止、特性曲线未完成堵转或数据不足为未完成。

KT：横轴为记录的实际下发目标扭矩，纵轴为平滑后的测功机输出Nm。
蓝线绘实测值，红线为y=x的理想线，范围自动跟随最大目标。
指标为max|平滑实际值-目标值|/最大目标×100%，即相对理想线的满量程误差。
该指标同时包含增益、零偏及非线性偏差，并非仅相对最佳拟合线的非线性。
按用户要求目标与Nm做1:1比较，5%是初版工程门槛；可按具体型号修改。
两项测试均按电机接收时间匹配测功机帧，一帧最多用一次，多余帧舍弃，
20ms内无匹配则留空。平滑先在各自完整采样上计算，再随原始帧一起匹配。

结束时控制台逐项打印实测指标、标准和PASS/FAIL/待定/未完成。
旧报告可运行 `python -m scripts.factory_test.rebuild <旧总测目录>` 另存新版。
旧KT没有目标列时只能按保存的斜坡时长重建理论目标，图下注明，原目录保留。

电机特性曲线：横轴为平滑后的电机速度，标注“转速 rad/s”；最大转速使用同一数据源。左轴为平滑后的测功机扭矩Nm，
右轴为平滑后的电机速度×平滑后的电机扭矩所得电机功率W。右侧只列关键参数，不作判定。

设备加载参数由各子脚本配置，扭矩输出误差当前默认24V/3A，特性曲线逐步加载至5A上限。
测试与故障后收尾不在报告模块中重复实现。故障时保留已完成CSV和未完成报告。
第一版进行了离线模拟验证，整套装置联调另行进行。
