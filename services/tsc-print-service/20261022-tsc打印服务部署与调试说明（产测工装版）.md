# TSC 标签打印服务 部署与调试说明（产测工装版）

> 版本：2026-10-22 ｜ 适用：产线模组测试工装工程师，在自己笔记本 + USB 标签打印机上调试打印功能
> 本包内容：打印桥接服务（源码 + Windows x64 预编译依赖，免安装依赖免联网）+ 本说明

## 1. 这是什么

本机打印桥接服务（Node.js）：接收 HTTP 请求 → 生成 CODE128 条码标签 → 经 Windows 打印驱动发给 USB 标签打印机。工装软件后续调它打印模组SN标签。

工装完整链路分两步，**本包只涉及第②步（打印）**：

```
① 工装 → MES 云端取模组SN     ← 需要 X-Api-Key 密钥（另行交付；调试打印机用不到）
② 工装 → 本机 127.0.0.1:9876  ← 打印，无需任何密钥
```

## 2. 前置条件

1. Windows 64 位笔记本（依赖已预编译为 win-x64，无需任何编译工具）
2. **Node.js ≥ 18**：https://nodejs.org 下载 LTS 版安装（一路默认）。装完在 cmd 执行 `node -v` 能出版本号
3. USB 连接标签打印机（TSC TE244 / 科然 4502 或 TSPL 兼容机型），**驱动已装好**——控制面板「打印机和扫描仪」里能看到它
4. 标签纸 50×15mm（与产线一致；用其他尺寸需改配置，见 §7）

## 3. 启动（三步）

1. 解压本包到**纯英文、无空格路径**（推荐 `D:\tsc-print-service`）
2. 双击 `start.cmd`，窗口应停留并显示：

   ```
   HTTP 地址:  http://127.0.0.1:9876
   ```

3. 浏览器打开 http://127.0.0.1:9876/api/status ，看到 JSON 即服务已正常

调试期间**保持窗口开着**（关窗口=停服务）。

## 4. 配置打印机名（关键一步）

浏览器开 `/api/status`，看两个值：

- `printerName`：服务当前使用的打印机名
- `allPrinters`：本机 Windows 里的全部打印机名

若 `printerName` 不在 `allPrinters` 里（或想换打印机）：记事本打开 `config.json`，把

```json
"printer": { "name": "这里改成 allPrinters 里的准确名字（整串照抄）", ... }
```

保存后**关掉 start.cmd 窗口、重新双击**重启，再开 `/api/status` 确认 `found: true`。

`online: true` = 打印机就绪，可以打。

## 5. 试打

cmd 直接执行（Win10+ 自带 curl）：

```bat
curl -X POST http://127.0.0.1:9876/api/print -H "Content-Type: application/json" -d "{\"items\":[{\"sn\":\"TEST-SN-0001\"}],\"copies\":1}"
```

应答 `success:true` 且打印机出一张 TEST-SN-0001 的 CODE128 条码标签。

批量与份数：

```bat
:: 3 个不同 SN 各 1 张（打印顺序=数组顺序）
curl -X POST http://127.0.0.1:9876/api/print -H "Content-Type: application/json" -d "{\"items\":[{\"sn\":\"TEST-0001\"},{\"sn\":\"TEST-0002\"},{\"sn\":\"TEST-0003\"}]}"

:: 1 个 SN 打 2 份
curl -X POST http://127.0.0.1:9876/api/print -H "Content-Type: application/json" -d "{\"items\":[{\"sn\":\"TEST-0001\"}],\"copies\":2}"
```

不想出纸只看打印指令：`POST /api/preview`（返回 TSPL 文本，不占打印机）。

## 6. 接口约定（工装软件对接时必读）

1. **顶层 `success:true` 只代表"至少一张进入了打印队列"**——必须逐条检查 `data.results[].success`，失败的 SN 单条重发
2. **响应要等全部打完才返回**，每张约 1-3 秒；HTTP 客户端超时按 ≥3 秒/张预留，单批超过 20 张建议分片调用
3. **超时后不要盲目重发**——可能打出重复标签；先核对已出的纸，再按缺失的 SN 补发
4. 请求级可用 `printerName` 参数临时覆盖默认打印机，一般不用

## 7. 标签规格与调整

当前 `config.json` 的 `label` 段已按产线定型：**50×15mm、间距 3mm、203dpi、浓度 10、速度 3**。换纸型/浓度时改 `label` 段对应项（width/height 单位 mm，density 0-15），改完重启服务生效。标签内容固定为：CODE128 条码（占宽 92%）+ 下方一行文字（无 wifiName 时仅 SN）。

## 8. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| `/api/status` 里 `found:false` | `config.json` 的 printer.name 与系统打印机名不一致（按 §4 抄准确名字）；或打印机未开机/USB 未连 |
| `found:true` 但 `online:false` | 打印机离线/缺纸/卡纸，看打印机指示灯与 Windows 打印队列 |
| 双击 start.cmd 窗口一闪而过 | 未装 Node.js 或版本低于 18；cmd 里 `node -v` 验证 |
| 启动没反应/9876 被占 | 端口占用时本服务会静默退出；cmd 里 `netstat -ano | findstr 9876` 查占用，或用 `node index.js --port 9875` 换端口 |
| 打印内容空白/错位/截断 | 标签纸实际尺寸与 config.json label 段不符；或 dpi 与机型不符（TE244=203） |
| 杀毒软件报拦截 | 服务通过 PowerShell（raw-print.ps1）调 Windows 打印队列，属正常行为，放行本目录即可 |

## 9. 与 MES 联调（调通打印机之后）

云端取模组SN的接口地址、参数枚举、X-Api-Key 由 MES 侧另行交付（文档：《模组SN获取与标签打印对接文档（工装侧）》）。**本阶段调打印不需要它们。**
